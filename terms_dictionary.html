📖 מילון מושגים מקיף: צד שרת, תקשורת וצ'אט

סיכום מעמיק של כל המושגים, הפרוטוקולים והכלים שלמדנו
1. תשתית, סביבת ריצה וארכיטקטורה
צד שרת / שרת Backend / Server
ההגדרה: התוכנה והלוגיקה שרצות על מחשב מרכזי מחוץ לדפדפן.
תפקידו להיות מקור האמת היחיד (Single Source of Truth), לתווך בין משתמשים, לשמור היסטוריה בבסיס נתונים, לאחסן קבצים ולבצע פעולות מאובטחות שהדפדפן אינו רשאי לבצע.
💡 אנלוגיה: המטבח במסעדה — הלקוחות לא נכנסים אליו ישירות, הטבחים מכינים בו את האוכל לפי הזמנות.
צד לקוח Frontend / Client
ההגדרה: כל מה שרץ בתוך הדפדפן של המשתמש (React, HTML, CSS).
אחראי על חוויית המשתמש (UI), עיצוב, תפיסת לחיצות וכפתורים, ושיקוף הנתונים שמגיעים מהשרת. אינו שומר מידע קבוע של משתמשים אחרים.
💡 אנלוגיה: חלל הישיבה והתפריט במסעדה.
נוד ג'יי אס Node.js
ההגדרה: סביבת הרצה המאפשרת להריץ קוד JavaScript ישירות על מערכת ההפעלה.
נוד אינו שרת בעצמו, אלא ה"מנוע" שמריץ את קובץ השרת שאתה כותב, ומעניק לו גישה לכרטיס הרשת, למערכת הקבצים בדיסק ולזיכרון המחשב.
💡 אנלוגיה: המנוע והדלק של הרכב שמאפשרים לו לנסוע על הכביש.
ניהול חבילות של נוד NPM / package.json
ההגדרה: מנהל החבילות ותעודת הזהות של הפרויקט.
הפקודה npm init -y מייצרת את קובץ ה-package.json שמפרט את שם הפרויקט, הגרסה, וכל הספריות החיצוניות שהותקנו לצורך ריצתו (Dependencies).
שער / פורט Port (e.g. 5000)
ההגדרה: נקודת קצה וירטואלית במערכת ההפעלה המאפשרת לנתב תעבורת רשת ליישום ספציפי.
למחשב יש עשרות אלפי פורטים. כשאנו מגדירים לשרת להאזין בפורט 5000, כל בקשה שמגיעה לכתובת המחשב עם סיומת זו מועברת ישירות לתוכנית השרת שלנו.
💡 אנלוגיה: מספר הדירה בבניין מגורים משותף.
2. פרוטוקולים, שיטות תקשורת ורשת
פרוטוקול HTTP HTTP (Hypertext Transfer Protocol)
ההגדרה: פרוטוקול תקשורת מבוסס בקשה-תשובה (Request-Response).
עקרון העבודה: הלקוח פונה בבקשה ← השרת מגיב ← החיבור נסגר מיד. השרת אינו יכול ליזום פנייה לדפדפן מיוזמתו. משמש לטעינת דפים, שליחת טפסים והעלאת קבצים.
💡 אנלוגיה: שליחת מכתב בדואר וקבלת מכתב תשובה בחזרה.
וובסוקט WebSocket
ההגדרה: פרוטוקול תקשורת דו-כיווני, רציף ופתוח בזמן אמת.
החיבור נפתח בבקשת שדרוג (Handshake) ולאחר מכן נשאר פתוח ברציפות. שני הצדדים יכולים לשדר נתונים בכל שבריר שנייה ללא צורך בפתיחת חיבור חדש.
💡 אנלוגיה: שיחת טלפון פתוחה שבה אף אחד לא מנתק את השפופרת.
סוקט.איי או Socket.IO
ההגדרה: ספריית JavaScript משוכללת מעל פרוטוקול WebSocket.
מעניקה ממשק אירועים פשוט (emit ו-on), חיבור מחדש אוטומטי במקרה של ניתוק רשת, וחלוקת משתמשים ל"חדרים" (Rooms) בקלות.
ארכיטקטורת REST API REST API
ההגדרה: סט מוסכמות עולמי לתכנון נתיבי שרת בצורה אחידה וקריאה.
הנתיבים מבוססים על שמות עצם ברבים (/api/messages) והפעולה נקבעת לפי סוג מתודת ה-HTTP הנשלחת (GET לקריאה, POST ליצירה, DELETE למחיקה, PUT/PATCH לעריכה).
3. אנטומיית הבקשה (Request) והתשובה (Response)
גוף הבקשה req.body
ההגדרה: התוכן המרכזי והכבד שנשלח מהלקוח (ב-POST/PUT).
מכיל בדרך כלל אובייקט JSON עם נתוני טופס או הודעה. נקרא על ידי השרת הודות ל-Middleware של express.json().
פרמטרי נתיב דינמיים req.params (e.g. :chatId)
ההגדרה: משתנים המוטמעים ישירות בתוך כתובת ה-URL ומוגדרים בעזרת נקודתיים.
משמשים להצבעה על פריט ספציפי ויחיד לפי מזהה ייחודי (ID). השרת לוכד את הערך שבין הסלאשים ושם אותו באובייקט req.params.
פרמטרי חיפוש וסינון req.query (?key=val)
ההגדרה: מחרוזת שאילתה המופיעה בסוף ה-URL לאחר סימן שאלה.
משמשת בעיקר בבקשות GET לצורך סינון, מיון, חיפוש טקסט או חלוקה לעמודים (Pagination) מבלי לשנות את מבנה הנתיב הבסיסי.
כותרות הבקשה req.headers
ההגדרה: מטא-דאטה (מידע על המידע) שנשלח לצד הבקשה.
משמש לציון סוג התוכן הנשלח (Content-Type: application/json), מפתחות אימות ואבטחה (Authorization Tokens), שפת הדפדפן ועוד.
💡 אנלוגיה: המדבקה והבולים המודבקים על גבי המעטפה.
קודי סטטוס HTTP HTTP Status Codes
ההגדרה: מספרים בינלאומיים המעידים על תוצאת הטיפול בבקשה.
• 200 OK: הבקשה הצליחה.
• 201 Created: הבקשה הצליחה ונוצר משאב חדש במערכת.
• 400 Bad Request: הלקוח שלח מידע לא תקין או חסר.
• 404 Not Found: הנתיב או הפריט המבוקש לא קיים.
• 500 Server Error: השרת נתקל בשגיאה פנימית וקרס.
4. עיבוד נתונים, קבצים ומדיה
ג'ייסון ומחרוזות JSON (stringify & parse)
ההגדרה: פורמט טקסטואלי סטנדרטי להעברת מבני נתונים ברשת.
כבל רשת אינו יכול להעביר אובייקטים של JS. JSON.stringify ממיר אובייקט למחרוזת טקסט לצורך שליחה, ו-JSON.parse (או response.json()) ממיר את הטקסט בחזרה לאובייקט בזיכרון.
טופס נתונים רב-חלקי FormData / multipart/form-data
ההגדרה: פורמט מיוחד לשליחת קבצים בינאריים יחד עם טקסט.
כשמעלים תמונה, מסמך או הקלטה, לא משתמשים ב-JSON אלא אורזים את הקובץ באובייקט FormData. הדפדפן מחלק את הבקשה למקטעים ומעביר את הבייטים בצורה יעילה.
מאלטר Multer
ההגדרה: ספריית Middleware של Express לקליטה ושמירת קבצים בדיסק.
מיירטת את הבייטים של הקובץ מהבקשה, נותנת לו שם ייחודי בדיסק (למניעת דריסת קבצים), שומרת אותו בתיקייה (כמו uploads/) ומעבירה לקוד שלנו את הפרטים בתוך req.file.
הגשת קבצים סטטיים express.static
ההגדרה: שיתוף תיקייה מקומית בדיסק ככתובות URL ציבוריות.
השורה app.use('/uploads', express.static('uploads')) הופכת את תיקיית הקבצים לזמינה ברשת, כך שכל דפדפן יכול להציג תמונה באמצעות כתובת פשוטה.
